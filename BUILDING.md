# Building BUDAT

Expo (SDK 54) React Native app, distributed to iOS via TestFlight using EAS.

## Build & submit to TestFlight

From an environment logged into EAS (see below):

```bash
eas build --platform ios --profile production --auto-submit
```

- `--profile production` — defined in `eas.json`; has `autoIncrement: true`, and with
  `appVersionSource: "remote"` EAS assigns the build number itself (no manual
  `buildNumber` bump needed).
- `--auto-submit` — uploads to TestFlight when the build finishes (uses the
  `submit.production` config in `eas.json`).

Add `--non-interactive` when running headless (CI, or an agent with a token).

## Auth options

**Interactive (your machine):** `eas login` once, then run the build command.

**Headless / token (e.g. for an agent to trigger builds):**

1. Create an access token at **expo.dev → Account settings → Access tokens**
   (`expo.dev/settings/access-tokens`). Copy it — shown only once.
2. Add it to the Claude Code web environment settings as an environment variable
   (`.env` format, no quotes):
   ```
   EXPO_TOKEN=<token>
   ```
3. Start a **new session** — env vars are injected at container start, so they
   don't apply to a session that was already running.

Notes:
- The Claude Code web environment has **no encrypted secrets store yet**; env vars
  are visible to anyone who can edit the environment. An Expo access token grants
  **full account access** — rotate/revoke it at expo.dev when no longer needed.
- `EXPO_TOKEN` is only needed to let an agent trigger builds; you can always run
  `eas build` yourself interactively.

## Dependency / SDK notes

This project pins native modules to the **SDK 54** line. Do **not** let a bare
`npm install <expo-pkg>` pull a version built for a newer SDK — a mismatched
native module (e.g. `expo-sensors` 55 vs SDK 54's `~15.0.8`) crashes on app
launch. Use `npx expo install <pkg>` so the SDK-correct version is chosen, and
verify with:

```bash
npx expo install --check
```

The peer-dependency graph requires `--legacy-peer-deps` for plain `npm install`.

## iOS permissions

The committed `ios/` project is **not** regenerated by prebuild on each build, so
privacy usage strings must exist in **both** `app.json` (`ios.infoPlist`) and the
committed `ios/BUDAT/Info.plist`. Currently required:

- `NSMicrophoneUsageDescription` — mic-based wind speed + audio notes
- `NSMotionUsageDescription` — compass/motion for wind direction
- `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription` — swell-log photos

If you regenerate native code with `npx expo prebuild --clean -p ios`, the
`Info.plist` is rebuilt from `app.json`, so keep `app.json` authoritative.

## Calibration (mic anemometer)

Long-press the **ANEMOMETER** title on the MIC page to open the hidden
calibration tool (SPEED / DIRECTION modes). Results are applied **manually**:

- **Speed:** collect points, copy the printed `DB_BREAKPOINTS` array, paste it
  over the one in `hooks/useMicWind.ts`.
- **Direction:** collect detected↔true pairs, read the compass offset, and apply
  it in `hooks/useMicWind.ts` where the magnetometer heading is computed.
